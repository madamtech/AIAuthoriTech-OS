# SOW control standard

## Source reconciliation

For each material term record:

- SOW section
- proposed language or value
- proposal or approved-source reference
- governing-agreement interaction
- owner
- approval status
- conflict or open question

## Deliverable test

Every deliverable must have:

- unique identifier
- included contents and format
- explicit exclusions
- prerequisite inputs
- responsible producer
- due event or approved date
- review window
- objective acceptance evidence
- acceptance authority
- correction and resubmission path from approved terms

## Change trigger examples

Record rather than pre-authorize:

- scope, volume, environment, integration, or data changes
- delayed client input or access
- new legal, security, privacy, or governance requirements
- third-party limitations
- acceptance-criteria changes
- schedule acceleration
- additional iterations, training, support, or deployment work
