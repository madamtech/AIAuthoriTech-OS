# n8n Planning Standard

Verify the target n8n edition, exact version, hosting model, execution mode, database, workers, queue, security configuration, and supported nodes before planning. Map each platform-neutral step to a verified native node, HTTP request, approved code, sub-workflow, or external service. Record expressions, item and binary-data shapes, pagination, batches, rate limits, credentials, environment variables, and state.

Design correlation, idempotency, concurrency, retries, error workflows, replay, reconciliation, retention, pruning, redaction, metrics, alerts, backups, scaling, disaster recovery, upgrades, and rollback. Keep secrets out of nodes, exports, logs, and fixtures. Review community nodes for provenance, permissions, maintenance, vulnerabilities, and compatibility before approval. Prove version-specific behavior outside production.
