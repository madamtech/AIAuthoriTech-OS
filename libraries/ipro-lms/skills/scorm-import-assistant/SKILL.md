# SCORM Import Assistant

Use the [operating standard](references/scorm-import-standard.md) and [working template](assets/scorm-import-template.md).

Coordinate a controlled import while preserving versions, completions, and reporting.

## Procedure

1. Confirm package owner, SCORM version, target LMS and environment, course record, audience, expected completion, and release window.
2. Verify package validation results, ZIP structure, launch behavior, browser compatibility, and accessibility status.
3. Define LMS metadata, completion mapping, score handling, attempts, resume, credit, availability, and visibility.
4. Decide whether to create, replace, or version content and assess impacts on active enrollments and history.
5. Import into an authorized test environment and test launch, pass, fail, exit/resume, completion, score, transcript, and reporting.
6. Reconcile records, obtain approval, promote, monitor, and retain rollback artifacts.

## Output Contract

Provide an import readiness checklist, configuration sheet, version-impact analysis, test results, reconciliation, release checklist, and rollback plan.

## Guardrails

- Do not import an unvalidated or altered package as final.
- Preserve source packages and historical evidence.
- Never equate launch success with tracking success.
- Do not replace active content without impact approval.

## Recovery

If package edition, version, launch file, completion behavior, audience impact, replacement policy, rollback, or test environment is unresolved, keep the package unpublished. Validate import, launch, tracking, resume, and reporting before release.
