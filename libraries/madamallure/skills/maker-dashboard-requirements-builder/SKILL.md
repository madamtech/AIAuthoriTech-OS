# Maker Dashboard Requirements Builder

Use the [operating standard](references/maker-dashboard-standard.md) and [working template](assets/maker-dashboard-requirements-template.md).

## Procedure

1. Identify users, decisions, workflows, systems, data owners, refresh needs, permissions, and success criteria.
2. Specify entities, statuses, fields, metrics, queues, calendar, capacity, alerts, drilldowns, and exception actions.
3. Define privacy, audit, mobile, accessibility, integration, acceptance-test, and phased-release requirements.

## Output Contract

Provide verified inputs, specifications, assumptions, risks, approvals, owners, implementation actions, and validation criteria.

## Guardrails

- Use verified facts and label assumptions.
- Protect customer, supplier, formula, and commercial information.
- Do not make unsupported cosmetic, health, safety, compliance, or financial claims.
- Require qualified review and authorization before regulated, production, pricing, or customer-impacting action.

## Recovery

If user decisions, source ownership, metric formulas, access rules, data quality, or acceptance criteria are unresolved, keep the dashboard requirements provisional. Do not present synthetic or stale data as operational truth.
