# GPT Visual Intelligence Enhancement Operating Standard

## 1. Additive installation rule
The enhancement supplements a host GPT. The host GPT remains authoritative for domain expertise, business policy, tone, compliance, and task-specific decision rules.

The enhancement may improve visual interpretation, prompting, routing, generation, editing, and quality assurance. It may not alter the host GPT's purpose or expand its authority beyond available tools and verified knowledge.

## 2. Execution pipeline

### Gate A — Host GPT preservation
Capture the host GPT's purpose, audience, active business, prohibited behavior, required outputs, and existing evaluation rules.

### Gate B — Visual task classification
Classify the request as one or more of:
- new image generation
- image editing or restoration
- identity or character continuity
- branded campaign asset
- product visualization
- course or presentation visual
- print or craft production asset
- 3D-reference image
- storyboard or cinematic concept
- visual workflow design

### Gate C — Input sufficiency
Verify that required source images and exact wording are available. A claimed prior image, opaque identifier, or unavailable reference is not a usable editing target.

### Gate D — Lock construction
Create a lock table for all elements that must remain exact. Explicit user instructions outrank saved preferences. Current-project requirements outrank general defaults.

### Gate E — Skill routing
Start with `personalized-capability-framework`, then select the smallest downstream chain that covers the task. Avoid activating skills that do not materially affect the output.

### Gate F — Prompt compilation
Compile the request into:
`subject + action + environment + composition + lighting + camera + materials + palette + style + exact text + output requirements + locks + exclusions + acceptance tests`.

### Gate G — Generation or edit
Use the appropriate image-capable tool. The skill package supplies intelligence and control; it is not a rendering engine.

### Gate H — Evaluation
Check intent, locks, text, composition, brand, technical destination, safety, rights risk, and delivery format.

### Gate I — Controlled revision
Freeze approved elements and modify only failed or newly requested elements.

## 3. Evaluation thresholds
A visual may be delivered when all critical gates pass. A numeric score can support comparison but cannot override a critical failure.

Recommended dimensions:
- intent alignment
- constraint preservation
- reference fidelity
- composition and hierarchy
- brand consistency
- technical suitability
- typography accuracy
- production readiness
- safety and rights handling

Critical failures include wrong identity, changed locked features, incorrect exact text, wrong required dimensions, added prohibited elements, missing transparency when essential, unsupported claims, and cross-brand contamination.

## 4. Clarification policy
Do not interrupt for optional preferences that can be safely inferred and labeled. Ask before execution when a missing input prevents accurate editing, identity preservation, exact wording, legal use, or production compatibility.

## 5. Expected improvement
The enhancement should produce:
- stronger first-pass visual briefs;
- fewer unrequested changes;
- better preservation during edits;
- consistent brand and project routing;
- clearer output specifications;
- repeatable revision behavior;
- transparent limitations when a tool cannot provide a requested file type or property.

It does not guarantee that every image model will render perfect text, anatomy, identity, vectors, transparency, or print-ready files. Those outcomes remain dependent on the rendering tool and post-production workflow.
