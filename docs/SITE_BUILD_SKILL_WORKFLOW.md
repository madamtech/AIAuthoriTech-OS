# Repeatable Immersive Site Build Skill Workflow

## Purpose

This document is the operational procedure for planning, designing, building, testing, launching, maintaining, and revising immersive business-building websites in Tanika Crawford's digital ecosystem.

It works together with:

- `docs/IMMERSIVE_BUSINESS_BUILDING_SITE_STANDARD.md`

That standard defines the architectural philosophy, visual language, planning principles, reusable skills, and ecosystem rules.

This workflow defines exactly **how to execute the work repeatedly** so future sites do not depend on memory, improvisation, or rebuilding the planning method from scratch.

---

# 1. Core Operating Principle

Every site must be treated as a **business destination**, not a decorated webpage.

The repeatable process is:

**DISCOVERY → BRAND TRANSLATION → BUILDING CONCEPT → DIFFERENTIATION → ROOM MAPPING → VISITOR JOURNEY → INTERACTION DESIGN → ASSISTANT DESIGN → CONTENT DESIGN → CONVERSION DESIGN → MOBILE ADAPTATION → TECHNICAL PLAN → BUILD PROMPT → BUILD → QA → LAUNCH → ANALYTICS → REVISION**

No phase should be skipped because later phases depend on decisions made earlier.

# 3. Source-of-Truth Hierarchy

When multiple notes disagree, use this order:

1. Latest explicit user instruction
2. Locked brand decision
3. Current approved site standard
4. Current project specification
5. Current product/service data
6. Older planning notes
7. Early brainstorms

Never allow an older brainstorm to override a newer locked decision.

Example:

- Retired name: Fused Allure
- Current approved name: **Allure Fusions**

The retired name must not return unless explicitly requested.

---

# 4. Decision Status System

Every important planning decision should be labeled.

## LOCKED
Do not change unless the user explicitly changes it.

Examples:
- Crawford Creative Suites is the master environmental reference.
- Sites use upscale modern business-building architecture.
- Allure Fusions is the current brand name.
- Each site must be architecturally distinct.
- Sites must not become generic flat websites.

## FLEXIBLE
Preferred direction that may change during design or testing.

Examples:
- Exact room order
- Precise animation duration
- Secondary CTA wording
- Decorative object placement
- Exact lounge furniture
- Specific secondary accent treatments

## EXPERIMENTAL
A feature to test before permanently adopting.

Examples:
- Voice concierge
- Ambient audio
- Advanced 3D transitions
- Session personalization
- Saved visitor state
- Persistent assistant memory
- Complex animated walkthroughs

Each project should include a visible decision log.

# 8. Phase 4 — Differentiation Gate

Every site must pass this gate before room planning is finalized.

## Clone Test

Ask:
- Could another ecosystem brand use this exact environment with only a logo swap?
- Are the room names generic?
- Are the transitions copied?
- Is the assistant role interchangeable?
- Is the signature interaction reused?
- Are the materials too similar?
- Is the emotional tone too similar?
- Is the spatial flow too similar?

If several answers are yes, redesign.

## Distinct-Site Scorecard

Rate each as PASS / NEEDS WORK.

- Architecture is unique
- Entry sequence is unique
- Primary interaction is unique
- Signature transition is unique
- Assistant personality is unique
- Room vocabulary is unique
- Materials are unique
- Lighting is unique
- Emotional tone is unique
- User journey emphasis is unique
- Mobile interpretation retains identity
- Site still feels related to Crawford Creative Suites

All items must pass before final approval.

# 9. Phase 5 — Room and Space Mapping

## Goal

Turn business functions into meaningful spaces.

## Brainstorm Broadly First

Create more possible rooms than needed.

For each candidate room record:

- Room name
- Business purpose
- Visitor purpose
- Information shown
- Interactive element
- CTA
- Required data
- Required assets
- Whether it needs its own room
- Whether it duplicates another room

## Room Approval Rule

A room should exist only if it does at least one of the following:
- teaches
- demonstrates
- personalizes
- routes
- converts
- builds trust
- showcases work
- helps compare
- captures project information

Remove rooms that exist only because the name sounds impressive.

## Deliverable

### ROOM MAP
For every room:
- Name
- Purpose
- Entry point
- Exit options
- Main interaction
- Content
- CTA
- Required data
- Mobile equivalent

# 10. Phase 6 — Visitor Journey Mapping

Map multiple visitor journeys, not just one.

## Required Journey Types

### First-Time Visitor
Arrival → orientation → guided exploration → result → conversion

### Knows Exactly What They Need
Arrival → direct navigation → target room → CTA

### Does Not Know What They Need
Arrival → concierge/diagnostic → recommended destination → education → CTA

### Returning Visitor
Return greeting → continue prior interest or start new path

### Mobile Visitor
Simplified environmental path without losing brand identity

### Accessibility/Reduced Motion Visitor
Same information and functionality without requiring animations

### Error/No-Match Visitor
Clear fallback instead of dead-end messaging

## Deliverable

### VISITOR FLOW MAP
For each visitor type:
- Start
- Decision points
- Destination
- Result
- CTA
- Exit path

# 11. Phase 7 — Environmental Navigation Design

## Primary Navigation

Use spatial objects where practical:
- doors
- elevators
- hallways
- directory boards
- displays
- stations
- rooms
- desks
- screens
- counters
- galleries

## Secondary Navigation

Always include a clear fallback.

Recommended:
**Explore**

Potential menu:
- Directory
- Services
- About
- Resources
- Start a Project
- Contact

## Orientation

Visitors must always know:
- where they are
- what they can do
- where they can go next

Use:
SITE > AREA > ROOM

Include:
- Previous
- Directory
- Next
- Return to Lobby

## Navigation Requirements

- no dead ends
- no unclear clickable objects
- no hidden essential navigation
- no repeated floor selection after a visitor already specified a destination
- preserve destination intent across transitions
- all environmental interactions require accessible alternatives

# 20. Phase 16 — Responsive Design

## Desktop
- richest spatial experience
- environmental transitions
- architectural depth
- interactive rooms

## Tablet
- preserve environment
- simplify movement
- avoid tiny controls

## Mobile
Do not shrink the desktop building.

Instead use:
- full-screen room cards
- swipe/tap movement
- simplified directory
- environmental headers
- contextual navigation
- reduced visual complexity
- preserved brand identity

For every desktop interaction, document its mobile equivalent.

---

# 21. Phase 17 — Accessibility

Required:
- semantic structure
- keyboard navigation
- visible focus states
- readable typography
- sufficient contrast
- alt text
- form labels
- screen-reader-friendly controls
- captions/transcripts for meaningful audio/video
- reduced-motion option
- non-motion route to the same information
- no essential instruction conveyed only by color
- accessible error states
- predictable navigation

Environmental immersion must never block accessibility.

---

# 22. Phase 18 — Motion and Audio

## Motion

For every animation define:
- purpose
- trigger
- duration
- interruptibility
- reduced-motion alternative
- mobile behavior
- performance impact

Do not animate just because animation is possible.

## Audio

Audio must be optional.

Provide:
- Sound On / Off
- no essential audio-only instruction
- natural voices
- site-specific personality
- respect autoplay restrictions

---

# 23. Phase 19 — Performance

Set a performance plan before adding heavy visual effects.

Requirements:
- compressed media
- optimized images
- optimized 3D assets
- lazy loading
- minimal simultaneous animation
- no unnecessary autoplay video
- avoid blocking initial render
- test mobile performance
- test slow network behavior
- test lower-powered devices

Premium means smooth and intentional, not heavy.

# 35. Definition of Done

A site is DONE only when:

- approved architectural concept is implemented
- distinct-site test passes
- room map is implemented
- visitor journeys work
- primary signature experience works
- concierge/assistant works
- mobile version is intentional
- accessibility checks pass
- forms work
- integrations work
- conversion path works
- analytics work
- SEO foundation exists
- content is final
- demo content is labeled
- no placeholders remain
- no fabricated claims remain
- no broken links remain
- performance is acceptable
- privacy/legal links are present where applicable
- rollback/version record exists
- launch checklist is complete

If any required item fails, the site is not complete.

# 38. Standard Testing Personas

Use repeatable test personas.

### Persona A — First-Time Curious Visitor
Does not know exactly what they need.

### Persona B — Direct Buyer
Knows exactly what service/product they want.

### Persona C — Mobile Visitor
Uses a phone and expects quick routing.

### Persona D — Accessibility Visitor
Uses keyboard and/or reduced motion.

### Persona E — Returning Visitor
Has prior session context if supported.

### Persona F — Confused Visitor
Uses vague terms.

### Persona G — Wrong-Destination Visitor
Chooses a room that does not match their need.

### Persona H — High-Intent Lead
Completes an assessment and wants next steps.

All critical paths should be tested using these personas.

# 41. Repeatable Skill Command

Future work can be initiated with:

**"Build this site using the Immersive Business Building Site Standard and the Repeatable Immersive Site Build Skill Workflow."**

The process should then:

1. Retrieve relevant existing brand/project context.
2. Apply locked ecosystem standards.
3. Complete the planning worksheet.
4. Identify gaps.
5. Resolve them from known context where possible.
6. Create the architecture.
7. Run the differentiation gate.
8. Create the room map.
9. Map visitor journeys.
10. Define interactions.
11. Define assistant behavior.
12. Define content.
13. Define conversion.
14. Define mobile.
15. Define integrations.
16. Generate the build prompt.
17. Build.
18. QA.
19. Launch.

# 42. Core Rule for Future Designers

Do not ask only:

**What should this website look like?**

Ask:

- What place has the visitor entered?
- Why are they here?
- What should happen next?
- What should they learn?
- What should they experience?
- What should they be able to accomplish?
- What should they leave with?
- What makes this place unmistakably different?
- How does it still belong to the Crawford Creative ecosystem?

That is the reusable skill process.
